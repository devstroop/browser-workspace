# Architecture Decision Records (ADRs)

ADRs capture durable decisions, their context, alternatives, consequences, and revisit conditions.

- Create an ADR when a choice materially affects architecture, security, compatibility, long-term maintenance, or migration cost.
- Link the ADR to the issue(s) that drove the decision.
- Keep superseded decisions; mark them superseded and link the replacement.
- Do not use ADRs as a substitute for implementation issues or detailed subsystem specifications.
- Decisions can be proposed and reviewed before being accepted.
