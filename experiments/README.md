# Experiments

Use this area for disposable prototypes, technical spikes, and comparative experiments. Experiments may use different languages or tools from the production browser.

Each non-trivial experiment should have:
- A linked issue.
- A question or hypothesis.
- A bounded scope and time budget.
- Reproduction steps and environment details.
- Results, limitations, and a recommendation.
- A decision to discard, repeat, retain as a tool, or propose product integration.

Do not let experimental code become an undocumented product dependency. Promote useful work through a product issue, architecture decision where needed, and reviewed product PR.
